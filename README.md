## 启动

使用 Node.js 24 或更新的兼容版本。

```sh
npm install
npm run dev
```

浏览器打开 http://127.0.0.1:5173/，先进入「MIDLINE · 中路试炼」开始界面。可查看胜利条件、操作说明并选择单人 AI 或玩家对战；选择模式后点击开始。`three.html` 同样提供开始界面，游戏内「设置」可返回主菜单。进入前不会启动战斗模拟。

图片、角色动画及音频的 `?url` 导入在开发／局域网服务中自动添加内容版本号，并使用浏览器长期缓存；刷新时可复用已下载资源，文件内容修改后自动换用新地址。构建预览对带内容哈希的资源采用相同策略，HTML、代码模块和未带版本的素材仍检查更新。首次应用缓存策略需要下载一次新地址的资源；刷新后的图片／音频解码、GPU 上传和场景初始化仍会执行，加载提示并不代表重新下载。强制刷新或禁用浏览器缓存时会重新请求资源。

```sh
npm test
npm run build
npm run preview
```

`build` 先执行 TypeScript 检查，再输出静态站点到 `dist/`。`preview` 默认在 http://127.0.0.1:4173/ 预览生产构建。

## 局域网双人对战

Windows 主机可以直接双击项目根目录的 **`启动局域网对战.vbs`**。图形窗口会自动启动服务，显示可分享的局域网网址，提供“复制网址”“打开游戏”“停止服务”和日志查看；默认使用 5180，端口被占用时自动寻找 5181–5190 的空闲端口。另一位玩家只需在浏览器打开复制的网址，无需安装项目。

对战期间保持启动器窗口打开；关闭窗口会停止该窗口启动的服务，不会关闭其他 Node.js 服务。首次使用仍需安装 Node.js 和项目依赖。如果系统不支持 VBS，可运行 `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File scripts/start-lan-gui.ps1` 打开同一窗口。

在作为主机的电脑运行：

```sh
npm install
npm run dev:lan
```

服务默认监听所有网卡的 **5180** 端口，终端会打印可供另一台电脑访问的局域网地址，例如：

```text
http://192.168.2.139:5180/three.html?map=howling&scene=match&online=1
```

两台电脑连接同一局域网，并打开终端打印的同一个局域网地址。第一名玩家点击“创建房间”，把六位房间码告诉另一名玩家；第二名玩家输入房间码加入。双方点击“准备”，三秒倒计时后开始。创建者为蓝方，加入者为红方；双方都使用亚索，操作沿用单人模式，各自拥有自己的镜头、HUD 和视野。

服务器统一运行每秒 60 次战斗模拟，约每秒 20 次同步状态及战斗事件；客户端只发送操作，使用约 80 毫秒的快照缓冲按连续时间轴插值显示，吸收网络抖动。保留正常兵线、防御塔，以及一血／首塔／100 补刀胜利条件。Esc 和切换窗口不会暂停共享对局，结算后双方准备即可重开。任一玩家断线会暂停比赛，保留席位 30 秒；原浏览器标签页会自动重连，超时或有人主动离开则关闭房间。

联机已恢复原来的 1920 渲染精度、完整画面增强和逐帧迷雾更新，不再自动降低分辨率。左上角显示延迟与 FPS，超过 200 毫秒没有新快照时显示同步等待。网络平滑仍使用连续快照缓冲；视野范围不变时复用迷雾目标场，相同像素不重复上传 GPU，角色图集和阴影投射物查找也有缓存。

进入场景时显示资源加载进度：地图、角色全部方向动作、小兵、技能特效、界面图标、战斗／环境音频以及背景音乐的播放准备完成后，预上传纹理、预编译图形程序，然后开放操作。资源失败会阻止进入并显示刷新重试。美术模式不再显示圆柱占位体。联机准备和重连恢复都要求服务器确认双方资源就绪；加载期间比赛不推进。背景音乐继续使用流式媒体，不解码整段五分钟 PCM。

如果另一台电脑打不开地址，请检查主机防火墙是否允许 Node.js 的专用网络入站连接，并确认 Wi-Fi 没有开启访客隔离。另一台电脑不要使用 `127.0.0.1`，那表示它自己。主机必须保持服务运行。`$env:PORT=5181; npm run dev:lan` 可修改端口。

当前是面向可信局域网好友的对战版本：房间保存在内存中，服务重启后失效；尚未提供账号、排位、公网部署和客户端预测。战斗由服务器裁定，但完整状态下发后由客户端绘制迷雾，尚不具备对抗修改客户端的视野保密能力。网络协议和房间集成测试见 `tests/multiplayer.test.ts`，服务端类型检查运行 `npm run check:server`。

## 操作

右侧「设置」只保留玩家可调选项，分为「操作设置」与「画质设置」。操作设置包含技能施法、镜头跟随与声音；画质设置包含画面精度、环境画质与视觉效果。场景诊断、灰盒对照、测试场与角色数值不显示在设置中。

技能施法可在「设置 → 操作设置 → 技能施法」中切换：默认按下释放，按下 Q/W/E/R 即施法；选择长按显示范围后，按住技能键显示范围与方向，松开释放。两种模式均支持点击底部技能图标进入瞄准，再左键确认；右键或 Esc 取消本次瞄准。设置在本机浏览器保存，原入口与 Three.js 入口共用。Q/Q3 显示出剑走廊，W 显示风墙位置，E 显示目标和突进终点，R 显示范围与可接的击飞英雄；无有效目标或冷却中使用红色提示。切换窗口、暂停、死亡和重开会取消待释放技能。

| 操作 | 效果 |
| --- | --- |
| 右键地面 | 移动，取消尚未完成的普攻前摇 |
| 右键敌方单位 | 追踪并普攻 |
| 左键单位 | 选择单位，查看血量 |
| Q | 向鼠标方向发射棱光箭，命中首个敌方英雄或小兵 |
| W | 向鼠标方向短冲刺，获得 0.6 秒减伤 |
| E | 在鼠标位置的施法范围内释放裂光阵，预警后造成伤害和减速 |
| S | 停止移动与攻击 |
| Esc | 暂停或继续 |
| Enter | 开始、继续或在结算后再来一局 |
| Y / 镜头按钮 | 切换跟随镜头与自由镜头 |
| 按住 Space | 临时将镜头拉回英雄，不改变自由镜头模式 |
| 方向键 | 移动镜头并进入自由镜头 |
| 中键拖动 | 拖动镜头，进入自由镜头 |
| 自由镜头贴近画布边缘 | 向对应方向移动镜头 |
| 滚轮 | 切换 1× / 1.5× 局部视角，不缩回全景 |
| 点击小地图 | 查看对应区域，进入自由镜头 |

走回己方出生点光圈内恢复生命和法力。防御塔优先攻击小兵，攻击塔下敌方英雄会吸引塔仇恨。残血敌方小兵血条旁会出现浅黄色标记，表示当前血量已低于一次普攻伤害。

按 **3**（或 Ctrl+3） 可让亚索停下吹箫，同步播放新增动画和音效，动画和音效持续循环，直到操作或受击打断；移动、攻击、施法、受击或按 S 可取消。

音效默认开启，首次点击或按键后解锁播放，可在 HUD 中关闭。切换到其他窗口时比赛自动暂停。 亚索安全赶路时会间歇播放新增的两段走路音频，持续移动约 2 秒后触发，轮换间隔 16–19 秒；接近敌人、攻击或受击会中断，播放期间 BGM 自动降低。

“背景音乐”现使用官方发布的嚎哭深渊 Early Game 完整原声，可独立开关与调音量。亚索普通 Q／EQ 交替使用用户提供的 Q-v1、Q-v2，R 使用用户 MP4 提取的音轨，源文件位于 `assets/source-materials/audio/亚索音频/`，运行版本及处理记录位于 `assets/audio/yasuo-user-v1/`。其余英雄音效使用 Riot 官网基础皮肤演示音轨截取版，来源与裁切记录见 `assets/audio/riot-original/`。补刀／结算提示与小兵普通受击仍保留通用合成提示，无独立脚步声。

战斗反馈试版：访问 `/?map=howling&practice=combat`。展开“训练工具”可试普攻、Q、E、Q3、R、慢放及反馈对比。命中刀光、短暂动作顿挫、受击回弹和补刀残影均由实际事件驱动；音效需单独开启，无脚步声。Q 的刀光会按预计接触时间重排播放节奏，伤害、攻速、位移与施法收招规则保持原值。

短硬直试版：英雄普攻命中造成 50ms、普通 Q 造成 70ms 的短硬直，随后同一目标获得 350ms 普通硬直保护；重复命中照常扣血，但不能刷新或叠加硬直。小兵攻击不控制，E 不增加硬直，Q3／R 保留原控制。已提交的攻击和技能继续完成；硬直中只缓冲最后一次有效移动、攻击、技能或停止指令，恢复后重新检查并执行。训练工具可切换“受击硬直”，使用“靶攻击我”“高频受击测试”检查脱身与反击。

## 已选定的亚索攻击循环

使用用户提供的A（高位→低位）、B（低位→高位）透明WebP，原文件逐字节存档于 `assets/heroes/yasuo/selected-2026-10-10/`。每段200×128、24帧、3秒；派生PNG图集逐帧保留RGBA像素，不剪帧、不重绘、不修改自带刀光。导入脚本 `scripts/import-yasuo-user-attacks.py` 只做本地校验和转换，不调用生成服务。

[原速A/B循环与48帧预览](http://127.0.0.1:5173/assets/hero-attacks/2026-10-10/yasuo/v14-user-selected/index.html)已包含在生产构建中。原速循环6秒；对局内保持原有0.19秒前摇和0.8秒释放后冷却，将两段各自的挥砍/收势时段映射到这两个逻辑阶段。A使用第7帧、B使用第11帧作为攻击释放姿态。伤害、射程、追踪弹和胜负规则不变，并未改造成正式亚索近战技能。

蓝方亚索已接入已有八向待机和走路。攻击只用用户提供的右下方向，不旋转或镜像伪造其他方向；走路→拔刀和收刀→走路目前仍是直接切换。每次实际释放普攻后A/B才轮换，取消未完成的前摇不推进轮换；动画跟随比赛时间，暂停冻结，重开复位。

## 亚索 16 帧走路与待机

亚索八个方向的走路、待机各有 16 帧，共 16 段、256 帧。加速走路保留 0.8 秒循环，普通走路放缓为 1.28 秒；受减速影响时步频随之降低，切换状态不重置脚步相位。待机仍为 0.8 秒。原有移动速度、角色尺寸和攻击动画不变。原版 8 帧素材保留。

[新旧同步对比与逐帧预览](http://127.0.0.1:5173/assets/hero-studies/2026-10-15/yasuo-locomotion16/index.html)支持暂停、逐帧、慢放及整数倍放大。运行图集位于 `assets/heroes/yasuo/locomotion16-2026-10-15/runtime/`，每张 512×512，包含 4×4 个 128×128 的透明帧。
